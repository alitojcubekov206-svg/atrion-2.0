# Работа над Atrion 2.0

Репозиторий: `https://github.com/alitojcubekov206-svg/atrion-2.0.git`. Поведение текущего серверного этапа — [SPEC.md](SPEC.md), устройство — [ARCHITECTURE.md](ARCHITECTURE.md), запуск и проверка — [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Обязательные ограничения

- Пользователь запретил изменять фронтенд. Не меняй `src/frontend/`, страницы и layout в `src/app/`, стили, публичные ассеты или пользовательские потоки. Серверные маршруты `src/app/api/` входят в текущий объём. Отдельная старая ветка с интерфейсами не разрешает переносить их в `main`. Исключение, явно разрешённое пользователем 2026-10-06 для 3D-генератора: кадрирование, уровень пола и режим «Разрез» в `src/frontend/components/three/ConceptViewer.tsx`, строка соответствия запросу в `src/app/dashboard/design-engine/page.tsx` и dev-маршрут `/playground/generator` (в production 404); там же — более короткий мобильный автоплей трёх шагов на главной (`src/frontend/components/three/ScrollShowcase.tsx`) и реалистичный режим в студии (кнопка «Реалистично», карточка прогресса, `src/frontend/realistic-3d.ts`). Другие изменения интерфейса по-прежнему требуют прямого запроса.
- Риггинг отложен. Текущий приоритет — серверная генерация 3D по произвольному тексту и дизайн дома. Требования к качеству — [docs/GENERATION_QUALITY.md](docs/GENERATION_QUALITY.md).
- Перед изменениями прочитай связанные документы и код, проверь `git status --short --branch`. Сохраняй пользовательские изменения. Не делай автоматически pull, reset, очистку файлов или обновление базы.
- Различай существующее поведение, требования и предложения. Документы пиши по-русски. Названия API, типов и путей сохраняй как в коде.
- Внешние API проверяй по официальной документации. Ключи и пользовательские данные не помещай в документы, коммиты и сообщения.

## Реализация

- `src/backend/` содержит сессии, квоты и AI; не импортирует frontend. `src/shared/` содержит чистые контракты и геометрию без секретов, Prisma и браузера. Клиент не импортирует backend.
- Приватные API используют `requireApiUser`; для операций с проектом проверяй владельца. AI-квота резервируется до запроса и возвращается при необработанной ошибке. Успешный локальный fallback расходует квоту.
- Сохраняй Free-ограничение генерации 3D и возврат резервирования при ошибке. Константы тарифов — `src/backend/plans.ts`.
- `size` — полные размеры до вращения; `rotation` — радианы XYZ. Учитывай `repeat`, `mirror`, `mesh` в геометрии и bounds; изменение общего контракта требует проверки существующих потребителей без самовольной переделки интерфейса.
- Сохраняй `.github/CODEOWNERS`. Не выдавай AI-концепт за инженерный расчёт или читаемый GLB за успешно проверенный импорт в Unity.
- Согласовывай новое поведение со спецификацией и архитектурой.

## Проверка и публикация

Для кода: `npm run test:backend`, `npx tsc --noEmit`, `npm run build`. Для генератора также выполни соответствующие скрипты из DEVELOPMENT. Проверяй инварианты, а не копии реализации. Для документации достаточно путей, ссылок и `git diff --check`.

Не запускай `prisma db push` против неизвестной или рабочей базы. Точно сообщай результат проверок и ограничения. Commit, push, merge и публикацию выполняй в пределах прямого запроса пользователя. Разрешение текущего пользователя внести серверные изменения в `main` не отменяет запрет на фронтенд.
