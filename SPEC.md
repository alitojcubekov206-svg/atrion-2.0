# Спецификация Atrion 2.0

Статус: описание подтверждённого поведения текущего приложения и целевого продукта. База — `main` / `26ea85d`, повторно проверенная 5 октября 2026 года. Ветка `codex/backend-rigging` добавляет серверный модуль и ручные редакторы 2D/3D. Пользователь затем подтвердил генерацию персонажа и рига по тексту как главный сценарий; требования — [CHARACTER_GENERATION.md](docs/CHARACTER_GENERATION.md). Это спецификация Atrion; генерируемые приложением blueprint чужих проектов не определяют его собственные требования.

## Назначение и пользователи

Сейчас Atrion превращает текстовую идею программного продукта в технический план и предоставляет редактор концептуальных 3D-моделей. Это подтверждено README, UI, API и типами.

Пользователь установил основной будущий фокус: **2D-риггинг персонажей**, то есть скелет и анимация плоского персонажа. Также подтверждены направления **3D-риггинг** и **создание/дизайн дома**. Дизайн дома включает более общий дизайн, а не только генерацию одного фасада. Детальная аудитория и метрики успеха ещё не определены. Существующий AI Architect сохраняется; решение о его дальнейшей роли не принято.

Роли: посетитель, пользователь Free, пользователь с действующим Pro. Отдельных ролей администратора, организации и совместной команды в схеме нет.

## Тарифные правила

Источник — [plans.ts](src/backend/plans.ts). Free: максимум 5 одновременно существующих проектов, 5 успешных 3D-генераций за всё время, 25 AI-запросов в UTC-день. Pro: число проектов и 3D-генераций не ограничено этими счётчиками, AI ограничен 300 запросами в день. Удаление проекта освобождает место; удаление/сброс сцены не возвращает использованную генерацию.

В UI указан Pro за 200 сом на 30 дней и ручной контакт через WhatsApp. Реальная ручная процедура выдачи доступа не описана кодом. Обещания активации в течение часа и приоритетной генерации не подтверждают соответствующих механизмов.

## Сценарии и приёмка

1. Пользователь создаёт проект, отвечает на интервью, получает blueprint. При повторном открытии план читается из базы. Другой пользователь не может прочитать или удалить его через приватный API.
2. Без AI-ключей поддерживаемые генераторы дают локальные результаты. Интерфейс не должен представлять этот режим как подтверждённый ответ внешнего AI.
3. При исчерпании лимита API возвращает код ошибки и UI объясняет причину. Ошибка генерации освобождает резервирование; успешный локальный fallback расходует его.
4. Пользователь редактирует 3D-деталь, отменяет и повторяет действие, экспортирует фактическую геометрию. Сохранение редактируемой сцены в серверную базу не входит в текущую основу.
5. Включённая проверка email закрывает приватные project/3D операции для неподтверждённого пользователя. Исключение: `/api/3d/providers` проверяет только наличие сессии и раскрывает лишь флаг конфигурации.
6. Reduced motion выключает декоративные эффекты. Возможность работать с геометрией остаётся доступной.

Эти критерии описывают ожидаемое поведение; перечень реально выполненных проверок хранится в [PROJECT_STATUS.md](docs/PROJECT_STATUS.md).

## Результат текущего этапа

Для 2D полного роста добавлен процесс «рисунок → настройка суставов → риг». Из JPEG/PNG/WebP создаётся встроенный WebP, доступна очистка белого фона; пользователь проверяет 19 точек. Результат содержит 14 костей, сетку с весами, клипы дыхания, приветствия и покачивания и сохраняется в JSON. Поза меняется перетаскиванием костей или числовыми полями, одна drag-операция отменяется одним шагом. Это skinning видимой иллюстрации; мимика и скрытые поверхности уровня Live2D остаются будущей работой. Контракт — [DESIGN_BACKEND.md](docs/DESIGN_BACKEND.md), интерфейс — [RIGGING_EDITOR.md](docs/RIGGING_EDITOR.md).

Реализованы `Rig2DDocument`, `Rig3DDocument`, `HouseDocument` версии 1; контракты ригов находятся в `src/shared/rigging`, дом и хранение — в `src/backend/design`, приватные API вычисления/хранения и модель Prisma `DesignDocument`. 2D поддерживает FK, pivots, affine-матрицы, linear/step keyframes, loop и pose override; 3D — rigid FK с сохранением bind pose, repeat/mirror и локальных mesh; дом — прямоугольные комнаты, этажи, стены с открытыми проёмами и flat/gable roof. Сохранение использует ownership и optimistic revision: чужие документы дают 404, устаревшая запись — 409.

Вычисления локальные, без внешнего AI и расходования AI/3D-квот. Технические ограничения: 1 MiB на JSON-запрос, 100 документов на пользователя, общий лимит дизайн-API 60 запросов в минуту на пользователя в памяти одного экземпляра; limiter отключён в development. Новых тарифных обещаний нет. Ассеты 2D представлены HTTPS-ссылками либо встроенными PNG/WebP до 256 KiB. Клиент декодирует загруженные изображения; сервер проверяет MIME, сигнатуру и лимиты встроенных данных. Отдельного бинарного хранилища нет. Форматы — [DESIGN_BACKEND.md](docs/DESIGN_BACKEND.md).

Добавлена страница `/dashboard/rigging`: Canvas 2D, overlay костей в ConceptViewer, позирование, ключи, undo/redo, JSON и статический GLB. Design Engine переносит явные 2D/Live2D/VTuber-запросы в форму генерации рисунка. Старые 3D API отклоняют их до списания квот. Добавлен первый этап генерации рисунка: Cloudflare Workers AI + FLUX по умолчанию (JPEG с фоном), OpenAI Image API по явной настройке (WebP с запросом прозрачного фона). Для рисунка нужны серверные данные доступа; локальная сборка рига доступна после проверки суставов. Редакторы используют единые shared-evaluators; существующий GLB exporter не добавляет skinning. Новая таблица не применялась к рабочей базе. Статус проверок — [PROJECT_STATUS.md](docs/PROJECT_STATUS.md).
