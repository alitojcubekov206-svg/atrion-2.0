# Персонаж и риг по тексту: требование пользователя

5 октября 2026 года пользователь уточнил основной сценарий: **генерировать персонажа и готовый риг по текстовому описанию**. Ручной редактор служит для исправлений результата. Он не заменяет генератор. По качеству пользователь ориентируется на переданный пример Ruan Mei в формате Live2D.

## Что подтверждено примером

Архив исследован локально как данные; его ассеты не включены в репозиторий. В нём 13 файлов: `.moc3`, `.model3.json`, `.cdi3.json`, `.physics3.json`, настройки VTube Studio, четыре атласа 8192×8192, два фона и описание автора. В display-info перечислены 179 параметров, 17 групп и 64 части; physics содержит 17 настроек и 78 выходов. Это количество записей в JSON, не число ArtMesh или костей. Анимация готовой модели в runtime пока не воспроизводилась.

Среди параметров есть глаза, брови, рот, наклоны головы и тела, волосы, одежда и аксессуары. Исходников `.cmo3`, PSD, 3D-модели и отдельных `.motion3.json` в архиве нет. Пример задаёт детализацию и характер движений; не означает согласие пользователя публиковать чужую модель в продукте.

## Граница текущей реализации

`Rig2DDocument` версии 1 поддерживает слои с жёсткой привязкой к костям. В нём нет mesh-деформаций, масок лица, параметрических выражений и физики. Редактор и образец из простых фигур проверяют FK, привязки и ключевые кадры. Они **не проходят приёмку генерации персонажа уровня референса**.

`src/backend/ai.ts` сейчас вызывает текстовый Chat Completions API и генератор 3D-примитивов. Добавлен отдельный первый этап: `/api/characters/concept` вызывает официальный OpenAI Image API, а форма в 2D-редакторе показывает и скачивает цельный рисунок. Пользователь выбрал OpenAI Image API. Сегментации, дорисовки скрытых частей и сборки Live2D пока нет. Design Engine переносит явное 2D/Live2D/VTuber-описание в форму, не запуская платный запрос автоматически. Старые 3D-маршруты отклоняют такие запросы до резервирования квот. Редактор не подставляет учебную куклу как якобы сгенерированный результат.

## Подключение первого этапа

Сервер читает `OPENAI_IMAGE_API_KEY`. Если отдельного ключа нет, допускается `OPENAI_API_KEY`, только когда текстовый `OPENAI_BASE_URL` пустой либо равен официальному `https://api.openai.com/v1`. Ключи Groq/сторонних endpoint не переиспользуются. Endpoint изображений фиксирован на официальном OpenAI. `OPENAI_IMAGE_MODEL` — `gpt-image-2.5-flare` по умолчанию либо `gpt-image-2.5-sunburst`. Формат — WebP с прозрачным фоном, 1024×1536, quality high, один рисунок. Реальный доступ аккаунта и художественное качество не проверены: локального ключа нет.

GET/POST требуют `requireApiUser`. После валидации описания и конфигурации POST резервирует один существующий AI-запрос; ошибка, некорректный ответ или отмена возвращают резерв. Автоматических повторов и demo fallback нет. Сервер не пишет prompt, ответ или ключ в лог. Изображение до 3 MiB возвращается в base64 с `stage:concept, rigReady:false`, без серверного хранения. Клиент проверяет декодирование, сохраняет предыдущий рисунок при ошибке и позволяет скачать WebP. Blob URL живёт только на странице и не выдаётся за постоянный rig-ассет.

Тайм-аут SDK — 150 секунд, клиента — 165; `maxDuration` нового маршрута — 180. Перед деплоем на Vercel нужно проверить Fluid compute: [официальные лимиты](https://vercel.com/docs/functions/configuring-functions/duration). Без Fluid на Hobby предел 60 секунд; такое окружение этому маршруту не подходит. Настройки hosting этой задачей не изменялись. Полный процесс генерации рига должен перейти на сохраняемые фоновые задачи, а не увеличивать один HTTP-запрос без ограничений.

## Необходимый производственный процесс

1. Описание → согласованный дизайн оригинального персонажа: пропорции, лицо, волосы, одежда, палитра, ракурс и стиль.
2. Рисунок → согласованные прозрачные части с дорисованными областями перекрытия. Сохраняются идентичность персонажа и качество контуров.
3. Части → сетки, pivots, порядок, маски и деформеры. Отдельно задаются глаза, рот, брови, голова, тело и аксессуары.
4. Параметры → моргание, взгляд, формы рта, наклоны, дыхание и вторичное движение волос/одежды. Физика воспроизводится с ограниченным шагом времени.
5. Автоматическая проверка → просмотр и ручное исправление → переносимый пакет с проверкой в целевом runtime.

Шаги должны иметь реальные состояния задачи, отмену, повтор после ошибки и результаты каждого этапа. Нельзя показывать фиктивный прогресс или завершение, если готовы только иллюстрация либо кости. Неуспешный запуск освобождает резерв квоты; AI-ошибка не заменяется учебной моделью.

Для больших ассетов требуется отдельное хранилище с проверкой владельца. Нынешние 256 KiB на встроенное изображение и 1 MiB на документ предназначены для простого редактора и не подходят для примера с четырьмя 8K-атласами. Нужны фоновые задачи, лимиты памяти и размера распакованного архива, сохранение версий результата; увеличение лимита JSON само по себе проблему не решает.

## Проверенные технические источники

- [OpenAI Image generation](https://developers.openai.com/api/docs/guides/image-generation): API генерации/редактирования растровых изображений. Не предоставляет готовый rig-документ; качество разбиения на согласованные части нужно проверять отдельно.
- [Live2D: About Models (Web)](https://docs.live2d.com/en/cubism-sdk-manual/model-web/): `.model3.json` связывает ресурсы, а `.moc3` содержит параметры изменения вершин. SDK загружает готовые модели; наличие runtime не доказывает автоматическое создание рига.

Конкретный метод подготовки слоёв и mesh-деформации ещё не проверен. API-адаптер, выбранный только по предполагаемому поведению провайдера, не должен внедряться как рабочий генератор.

## Приёмка

На нескольких независимых текстовых описаниях результат соответствует внешности и одежде, а не выбирает одну и ту же заготовку. Лицо сохраняет форму при крайних поворотах; веки закрывают глаз без дыр, рот не разрывает лицо, волосы не обрезаются. Нет щелей между частями и заметного фона в прозрачных областях. Моргание, взгляд, рот, дыхание и физика работают вместе. Экспорт/импорт сохраняет модель и поведение. Эти визуальные проверки пока не выполнены; генерация по тексту остаётся незавершённой задачей.
