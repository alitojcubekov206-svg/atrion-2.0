# Skills и MCP для разработки Atrion

Состояние проверено 5 октября 2026 года. Здесь описаны инструменты Codex, а не runtime-интеграции приложения.

## Проектные навыки

Навыки находятся в `.agents/skills`, области репозитория, поддерживаемой [официальной документацией Codex](https://learn.chatgpt.com/docs/build-skills). Они автоматически доступны для подходящих задач после обнаружения клиентом; также можно вызвать явно:

| Навык | Назначение |
| --- | --- |
| [$atrion-2d-rigging](../.agents/skills/atrion-2d-rigging/SKILL.md) | Слои персонажа, кости, pivots, FK, timeline и проверка анимации |
| [$atrion-3d-rigging](../.agents/skills/atrion-3d-rigging/SKILL.md) | Привязки 3D-деталей, pose, transforms и экспорт |
| [$atrion-house-design](../.agents/skills/atrion-house-design/SKILL.md) | Создание дома, планировка, appearance и согласованная 3D-проекция |

Они сохраняют границу фактов и предложений и не разрешают автоматически реализацию отложенного кода. Навык — инструкции агенту, а не установленный движок риггинга или генератор.

## Фактически доступное и подготовленное

| Инструмент | Проверенный статус | Польза |
| --- | --- | --- |
| GitHub plugin/connector | Установлен; `get_repo` и чтение `main` успешны для нужного репозитория | Анализ кода, issues/PR/CI в пределах запроса; ничего не публиковалось |
| OpenAI Docs MCP | Добавлен в проектную config; CLI видит enabled; initialize, tools/list и documentation search по HTTP успешны | Актуальные OpenAI/Codex docs, без ключа API |
| Shell, Git, Python/Node | Доступны в текущем окружении | Локальные файлы и проверки |
| Встроенный browser/image tools | Доступны в текущем чате | Просмотр будущего UI и подготовка изображений по запросу |
| Figma plugin | Найден в каталоге, installed=false; не подключался | Опциональный будущий обмен UI-макетами; не нужен для FK |
| Spine/Blender MCP | Поиск по этим именам не вернул отдельного подходящего плагина | Не добавлены; отсутствие в результатах не доказывает отсутствие во всём каталоге |
| Neon/storage MCP | В этой задаче не подключался и не проверялся | Для документации и ручного браузерного риггинга не требуется доступ к рабочей базе |

Для GitHub повторный вход сейчас не нужен: доступ подтверждён. Глобальная конфигурация уже содержит GitHub; дублирующий сервер в проекте не создавался. Ранее предложенное подключение не повторялось.

## Минимальная конфигурация

Файл [.codex/config.toml](../.codex/config.toml):

```toml
[mcp_servers.openaiDeveloperDocs]
url = "https://developers.openai.com/mcp"
```

Это официальный публичный documentation-only endpoint. Он не вызывает AI API и не предоставляет генерацию ассетов. Проектные настройки читаются для trusted projects; формат и область подтверждены [документацией MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), endpoint — [OpenAI Docs MCP](https://developers.openai.com/learn/docs-mcp).

Проверить из корня:

```powershell
codex mcp list
codex mcp get openaiDeveloperDocs
```

Не выполняй повторно `codex mcp add`: проектный файл уже есть; команда add создала бы глобальную запись. OAuth для этого публичного Docs MCP не требуется. Значение auth_status в listing было `unknown`, а доступность дополнительно подтверждена реальным HTTP MCP запросом.

Перечень инструментов уже работающего чата может не обновиться от изменения файла. Если OpenAI Docs search/fetch не появились, открой новый локальный чат для этого проекта и проверь список MCP; не считай успешную config автоматическим появлением tool в текущем сеансе. Skills клиент обычно обнаруживает автоматически; если они не видны, обнови локальный клиент согласно его документации.

## Что нужно для будущих функций

Ручной 2D-риг, FK и timeline можно разработать локально без стороннего сервиса. Для layers нужны реальные входные изображения. Автосегментация, дорисовка, генерация анимации или коммерческий экспорт потребуют выбора конкретного API/SDK и лицензии; их endpoints и ключи сейчас не придуманы. Для 3D сначала можно использовать существующие примитивы; для дома — параметрическую модель.

Настройка asset storage и production-БД выполняется после выбора persistence, отдельно от MCP разработки. Figma имеет смысл подключать, если пользователь принесёт Figma-макет; тогда потребуется его OAuth и доступ к файлу. Сейчас обязательных новых OAuth-действий для GitHub/Docs нет.

Никакие секреты, PAT или значения `.env` не сохранены в репозиторной config. Существующие пользовательские MCP и permissions не менялись. Единственное дополнение — публичный Docs MCP в области этого проекта.
