# Редактор ригов

Маршрут `/dashboard/rigging?mode=rig2d` либо `mode=rig3d` требует обычного входа. Для разработки без БД есть `/playground/rigging`; в production этот маршрут возвращает 404. Генерация рисунка по описанию через Cloudflare + FLUX либо OpenAI требует входа и серверных данных доступа. Результат скачивается в JPEG либо WebP и передаётся в подготовку полного роста. В preview можно загрузить свой рисунок. Полная генерация уровня Live2D остаётся целью [CHARACTER_GENERATION.md](CHARACTER_GENERATION.md).

## Полный рост с деформацией

«Риг из рисунка в полный рост» принимает JPEG/PNG/WebP до 8 MiB. Изображение уменьшается до 1024 по большей стороне и сохраняется как WebP до 256 KiB. На белом фоне доступна очистка связанных с краями белых областей с регулируемым допуском; белые просветы внутри контура удаляются отдельными кликами. Это цветовая заливка, не AI-сегментация. Исходный файл не изменяется. Для сложного фона нужен подготовленный прозрачный рисунок.

Начальная раскладка 19 точек пропорциональна габаритам видимого рисунка; это не распознавание анатомии. Пользователь совмещает точки с суставами мышью, стрелками или координатами. Одно перетаскивание — один шаг отмены. Сборка создаёт 14 костей, общую треугольную сетку занятых пикселями ячеек и нормированные веса ближайших связанных костей. Текстура непрерывно деформируется по текущим и исходным матрицам. Сетка может отображаться поверх рисунка.

Добавляются редактируемые клипы «Дыхание», «Приветствие» и «Покачивание». Над холстом расположены кнопки каждого движения и паузы. После сборки и при открытии готового локального fullbody-примера автоматически запускается приветствие. Воспроизведение и scrub временно показывают позу клипа, не перезаписывая сохранённую ручную позу; пауза сохраняет текущий кадр. Для позирования тянут кость на холсте; drag изменяет FK-угол и даёт один undo-step. Сборка нового рига также отменяется: предыдущая работа остаётся в undo, сохранённый серверный документ не перезаписывается. Доступны прежние числовые поля, ключи, play/pause/scrub, JSON, восстановление черновика. Удаление кости, используемой весами, блокируется; повторная подготовка рисунка позволяет пересобрать скелет. JSON переносит WebP, mesh, веса, кости, clips и текущую позу. Действующий лимит документа остаётся 1 MiB.

Сетка имеет разделение между ногами ниже бёдер: вершины на средней линии дублируются, а веса нижней части ограничены соответствующей ногой. Это предотвращает перенос движения одной голени на соседний сапог при небольшом расстоянии между ногами. Требуется фронтальный рисунок с раздельными ногами; перекрещённые конечности этим методом не восстанавливаются.

При сильных поворотах возможны растяжение текстуры и схлопывание сетки. Одна иллюстрация не содержит скрытых поверхностей, отдельных век/рта или задних слоёв волос. Их дорисовка, мимика, физика, IK и экспорт Live2D здесь не реализованы.

## 2D

Редактор Canvas отображает слои и кости. Отдельные PNG/WebP загружаются как слои; можно менять pivot, положение, угол, масштаб, порядок и видимость, назначать кость. При смене привязки и удалении конечной кости положение изображения сохраняется. Если преобразование со сдвигом от неравномерного масштаба нельзя выразить через position/rotation/scale, операция отклоняется без изменения документа.

«+ Кость» включает создание двумя кликами: начало и конец на холсте. Выбранная кость становится родителем. «Вместить риг» показывает все кости и слои. В режиме «Править исходный скелет» меняются bind transforms; смена родителя сохраняет локальные координаты. В обычном режиме изменяется поза. Углы в интерфейсе — градусы, в JSON — радианы.

Доступны клипы, linear/step ключевые кадры, loop, воспроизведение, пауза и ползунок времени. Новый ключ заменяет существующий в том же времени. «Сбросить позу» выключает клип и возвращает bind pose. Учебный персонаж нарисован в коде и служит проверке механики, а не примером качества AI-генерации.

## 3D

Редактор использует `ConceptViewer` с отображением костей. Можно добавить кость, изменить parent и bind, выбрать деталь, назначить привязку и позировать. При смене привязки repeat/mirror разворачиваются в отдельные детали с сохранением их видимого положения. Удаление родителя с потомками запрещено до перепривязки детей.

Из панели Design Engine модель передаётся через sessionStorage; также принимается JSON `ThreeDConcept`. Импорт создаёт безопасные ID деталей и корневую кость. Существующая сцена остаётся в своём редакторе; прямое CAD/CSG-редактирование ригнутых деталей здесь не добавлено.

GLB экспортирует видимую **статическую позу**. Он не содержит skin/weights или анимационного скелета. 3D timeline, skinning, IK и импорт GLB/FBX-скелета отсутствуют.

## Сохранение и восстановление

До 30 шагов undo/redo находятся в памяти. Черновик автоматически хранится локально отдельно для 2D, 3D и страницы проверки. JSON переносит документ и текущую позу; PNG/WebP до 256 KiB встраиваются в него. Серверный лимит — 1 MiB на весь запрос. HTTPS-ассеты остаются внешними ссылками и требуют доступного источника.

Кнопки сохранения и открытия используют приватный дизайн-API с revision. Ошибка API либо импорта сохраняет текущую работу. Для серверного хранения необходима таблица DesignDocument; локальная проверка UI не доказывает работу с PostgreSQL. «Новый пример» явно заменяет открытый документ с подтверждением при изменениях.

Математика и валидация: `src/shared/rigging`; UI: `src/frontend/rigging`; backend хранит и проверяет через те же контракты. Статус проверок — [PROJECT_STATUS.md](PROJECT_STATUS.md).
