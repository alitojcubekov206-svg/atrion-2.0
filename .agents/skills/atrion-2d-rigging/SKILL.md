# 2D-риггинг персонажей Atrion

Найди корень Git-репозитория и проверь remote `alitojcubekov206-svg/atrion-2.0`. Читай корневой `AGENTS.md` и [целевую спецификацию](../../../docs/RIGGING_2D.md), а для общих границ — [ARCHITECTURE.md](../../../ARCHITECTURE.md). Shared FK и ручной редактор реализованы. Приоритет пользователя — генерация по тексту уровня Live2D; читай [требования](../../../docs/CHARACTER_GENERATION.md) и не выдавай учебный пример за генерацию. Текущий запрос разрешает backend, GitHub и интерфейс 2D/3D-риггинга. Контракты — [DESIGN_BACKEND.md](../../../docs/DESIGN_BACKEND.md).

## Выбор подхода

Сначала установи вид входа: отдельные PNG-слои, единый рисунок или готовый rig-документ. Отдельные слои подходят для ручного жёсткого рига. Цельный рисунок не содержит разделённых конечностей; не обещай автоматическую сегментацию или дорисовку без выбранного и проверенного метода. Не подменяй запрос набором независимых анимированных картинок.

Для первого редактора предпочитай локальные FK и keyframes без сети на каждый кадр. Уточняй IK, deformation и внешний экспорт только если они влияют на текущий результат. Не внедряй зависимость Spine/Live2D только по названию функции.

## Значимые инварианты

- Разделяй математическое пространство (+y вверх), экранное (+y вниз) и локальные offsets. Углы документа в радианах; conversion в градусы — на UI-границе.
- Храни bind pose отдельно от текущего pose и clip. Attachment умножается на world transform кости ровно один раз.
- Дерево костей не содержит циклов и неизвестных родителей. Reparent имеет явную семантику сохранения world/local pose.
- Evaluator получает секунды; play и scrub используют его одинаково. FPS не меняет конечный pose. Определи wrap-углы и duplicate key policy.
- Редактирование drag даёт один undo-step. Import-error сохраняет открытую работу.
- JSON с blob URL не является переносимым персонажем. Export package должен иметь реальные ассеты либо явно требовать стабильные внешние ссылки.

## Реализация и проверка по отдельному запросу

Держи чистые types/FK/evaluator в shared, UI/input/renderer во frontend, persistence/access-validation в backend. Не импортируй backend в клиент. Вначале выбери renderer и storage по реальным ограничениям; не представляй предложенные пути как существующие.

Проверь двухкостную цепь с аналитическим поворотом π/2, bind reset, cycle rejection, clip midpoint при разных FPS и export/import с ассетами. Затем проверь визуально pivot, порядок слоёв, play/pause/scrub и undo/redo. Для кода выполняй принятые в репозитории type/build checks. В отчёте отделяй проверенную анимацию от неподдерживаемых сегментации, skinning и форматов.
